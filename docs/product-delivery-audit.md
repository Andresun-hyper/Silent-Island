## 4. 收尾清单与有限关闭条件

这是用户原始要求，不是审计新增动效 scope。保留“写入成功后才显示成功 / 造景”的原有提交顺序。

关闭条件：最终有效 3D 渲染器中，文字能可辨识地组成鸟或所选造景，至少留存入场、停留、出场的短录屏或分阶段截图及触发步骤；说明出场由什么操作或周期触发。不能仅提交 phase 值或旧 2D 的动画代码。短正文与普通中文正文均可用，暂停 / 减少动态仍能完成操作；换地点或删除后不能只靠突兀清空来宣称已验收出场。不要求重做字体绘制引擎或增加新造景类型。

### A2. PNG / JSON 真正可带走：主线程进行中

关闭条件：由实际应用操作取得 PNG 和 JSON 文件，并记录文件名、尺寸 / 字节数、所在位置或哈希。打开 PNG 确认当前风景非空、文字 / 地点 / 日期可读；把实际导出的 JSON 导入隔离测试存储，核对正文、地点、天气、造景与删除标记。重复导入不重复，旧备份不复活纸篓条目，非法备份不改变原记录。已有单元测试可支持数据语义，但不能代替这次文件往返。

`docs/verification.md` 和 `docs/verification-three.md` 均明确承认尚未确认下载完成。关闭此项后应以真实文件证据更新结论，不只删除限制文字。无需另加 PDF、分享服务或云端导出。

### A3. 声音结果与状态一致性：仍缺实际验收

参考包括竹 / 木风铃、安静溪流、弓奏筝、池畔风声。记录已存在，但文档明确说未试听参考录音，也未证明合成声景听感。本轮不重新联网核验这些链接或授权标签；授权标签是历史记录，不是新的法律结论。因未打包参考录音，不把“下载素材 / 补录音授权”列为本版交付阻断。

### A5. 本地闭环与失败保护：已实现，需针对性回归

沿用现有功能做一条链：草稿关闭重开 → 保存 → 刷新 → 搜索 / 天气筛选 → 修改 → 纸篓 → 恢复 → 回到对应地点。另选第 13 条较早手记，确认其可回看且显示上限不导致数据丢失。这里要求的是实际动作和结果，不是重新实现或逐一补齐所有自动化 UI 测试。

PRD 的失败承诺也须留证据：损坏的本地 JSON 读取失败不覆盖原串且可导出；模拟写入失败时保留输入、不报成功；非法导入不改数据。`tests/journal.test.mjs` 没有 React / localStorage / 下载接口的替身，不能证明这些界面路径。

**另一个静态反馈缺口：** 在阅读面板“移到纸篓”时，wrapper `:247-249` 的 `commit()` 失败会保留阅读面板并设置 error；但全局错误 `:281` 要求没有面板，阅读分支 `:301` 又没有渲染 error（写作 / 列表 / 设置才有）。因此该失败路径可能没有可见提示。数据未见因此被删除，但用户不能获知失败。纳入既有失败保护验收，避免仅凭 `catch` 存在就签收。

## 6. 最终签收口径

只有当 A1 / A2 的实际结果、A3 的试听与状态闭环、A4 / A5 的限定回归以及 A6 的最终检查 / 远端提交证据对应同一交付版本时，才写“全部交付完成”。仍未验证的真机、性能或跨浏览器范围必须如实保留，不能用本文或其他文档中的“已实现”替换实测证据。

本次未发现必须新增产品模块才能完成原目标的理由。优先完成已知进行中的工作、修正已存在控制流的反馈缺口并补齐有限验收，不继续扩大场景、玩法或技术栈。
